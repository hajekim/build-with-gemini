왜 단일(Monolithic) 에이전트가 아닌 Orchestrator-Worker 패턴인가?
참고: AgentPatterns.ai - Orchestrator-Worker Pattern

소프트웨어 엔지니어링에서 멀티 에이전트를 도입하는 주된 이유는 '역할 분담'과 '도구 격리'입니다. 단일 에이전트에 수십 개의 시스템 도구와 규정을 몰아넣으면 모델의 컨텍스트 윈도우가 빠르게 포화되고 엉뚱한 도구를 호출하는 오류가 빈번해집니다. AgentPatterns.ai의 Orchestrator-Worker 패턴은 이를 중앙 리드 에이전트와 전문 워커로 명확히 분리하여 해결합니다.

1 도구 스키마 오염(Tool Schema Pollution) 방지

단일 프롬프트에 인사·전산·규정 등 15개 이상의 도구 스키마를 동시에 주입하면, LLM이 유사한 이름의 도구를 혼동하거나 불필요한 인자를 날조하는 환각이 급증합니다. 워커 단위로 필요한 최소 도구만 바인딩(Subagent Schema-Level Tool Filtering)함으로써 도구 호출 정확도를 극대화합니다.

2 규정 우선(Policy-First) 거버넌스 파이프라인 강제

단일 에이전트는 사용자가 "휴가 상신해 줘"라고 요구하면 사내 복무 규정 검증을 건너뛰고 곧바로 SaaS API를 호출하는 위험이 있습니다. 오케스트레이터는 작업 순서를 엄격히 제어하여, 반드시 규정 선검증 전문가(hr_policy_agent)의 승인 및 근거 조항을 확보한 뒤에만 SaaS 워커에게 작업을 위임하도록 강제합니다.

3 시스템 권한 격리 및 최소 권한 원칙(Least Privilege)

인사 시스템(WorkWeek)과 IT 전산 시스템(ServiceImmediately)의 인증 토큰과 API 접근 범위를 워커별로 물리적으로 격리합니다. 전산 지원 워커가 임직원의 민감한 인사 평가나 잔여 연차 데이터에 접근하거나 임의로 변조하는 것을 원천 차단합니다.

4 독립적 오류 진단 및 점진적 품질 개선 (Hillclimbing)

단일 에이전트 실패는 어디서 문제가 발생했는지 파악하기 어렵습니다. Orchestrator-Worker 구조에서는 오케스트레이터의 라우팅 실패인지, RAG 워커의 검색 실패인지, SaaS 워커의 API 연동 오류인지 명확히 분리되며, 각 워커의 프롬프트와 툴셋을 개별적으로 튜닝하고 평가(Eval)할 수 있습니다.

Google Agent Platform 공식 툴체인: agents-cli 아키텍처 가이드 ADK 2.3.0 Ecosystem

agents-cli란: 단순한 코드 생성기를 넘어, 에이전트의 스캐폴딩(create) • 의존성 동기화(install) • 로컬 추론(run) • 대화형 디버깅(playground) • 정량 평가(eval) • 프로덕션 배포(deploy) • 사내 레지스트리 공개(publish)까지 엔드-투-엔드 라이프사이클 전 과정을 표준화한 Google Cloud 공식 프레임워크입니다.

로컬 이너루프 (run & playground)

agents-cli run "질의"로 터미널에서 즉시 스트리밍 추론을 검증하고, agents-cli playground로 ADK 공식 시각적 웹 대시보드를 구동합니다.

배포 및 거버넌스 (deploy & publish)

agents-cli deploy 한 줄로 Cloud Run 컨테이너를 빌드/배포하고, agents-cli publish gemini-enterprise로 사내 갤러리에 A2A로 등록합니다.

프로젝트 전용 가상 환경 동기화 (agents-cli install)

프로젝트 디렉터리에서 agents-cli install을 실행하면, pyproject.toml에 선언된 170여 개 공식 패키지가 프로젝트 전용 가상 환경(.venv)에 자동 동기화(uv sync)됩니다. 

cd ~/enterprise-ops-agent && agents-cli install

2. 설계서(SDD.md) 및 사내 규정 원본 다운로드

GCS 기본 / curl 백업

소프트웨어 설계서(SDD)의 목적: 프롬프트에 방대한 코드를 일일이 나열하지 않고, 시스템 명세서, 데이터 모델, 도구 인터페이스 규격을 단일 문서로 정의하여 에이전트에게 맥락으로 주입하는 설계서 기반 프롬프트 엔지니어링(Spec-Driven Development)의 핵심 기준 문서입니다.

제 1 절: 시스템 개요

사용 모델(Gemini 3.8 Flash), RAG 신뢰도 임계값(0.80), 기본 사번(EMP-10294) 등 런타임 기준을 정의합니다.

제 2 절: 도구 명세

사내 복무/IT 규정 RAG 도구와 WorkWeek 연차 API, ServiceImmediately IT 티켓 API의 파라미터 및 반환값을 선언합니다.

FastMCP 프로토콜이란: Anthropic과 오픈소스 커뮤니티가 주도하는 Model Context Protocol(MCP)을 가벼운 Streamable HTTP 기반으로 구현한 규격입니다. 에이전트가 브라우저나 복잡한 프로세스 통신 없이도 표준 REST 엔드포인트를 통해 사내 SaaS 시스템의 도구를 원격 실행할 수 있습니다.
